# DoodleFace

한 PC·한 브라우저·한 카메라 앞에서 두 사람이 나란히 플레이하는 로컬 게임입니다. 상단 **11 DoodleFace** 탭 또는 `/#doodleface`로 엽니다. `npm run dev` 후 localhost에서 실행하거나, 빌드 결과를 HTTPS 정적 호스팅으로 제공합니다. 게임용 서버, 방, WebRTC, WebSocket, SSE, 환경변수, 외부 CDN을 사용하지 않습니다. Vite 개발 서버 자체의 HMR은 게임 통신과 무관합니다.

## 사용법

1. **2인 게임 시작 ＋**을 누르고 카메라 권한을 허용합니다. 오디오는 요청하지 않습니다.
2. 거울 화면에서 왼쪽 사람은 PLAYER 1, 오른쪽 사람은 PLAYER 2입니다. 얼굴과 조작하는 손을 자기 쪽 카메라 절반에 둡니다. 한 사람당 한 손으로 조작합니다.
3. 두 얼굴이 650ms 동안 안정적으로 보이면 5초 카운트다운을 진행합니다. 얼굴이 사라지면 준비 상태로 돌아갑니다.
4. 두 화면이 850ms 동안 서로의 자리로 이동합니다. 데스크톱은 좌우, 세로 모바일은 위아래로 이동합니다. 이동이 끝난 뒤 60초가 시작됩니다.
5. PLAYER 1의 손은 왼쪽(모바일 위) 화면의 PLAYER 2 얼굴에, PLAYER 2의 손은 오른쪽(모바일 아래) 화면의 PLAYER 1 얼굴에 그립니다.
6. 엄지·검지 끝 중간이 연필촉입니다. 두 손가락을 맞대어 상대 얼굴 **안에서** 획을 시작합니다. 시작한 획은 얼굴 밖에서도 이어집니다. 색상 위에서 새 Pinch를 시작하거나 색상 버튼을 클릭하면 자기 연필 색이 바뀝니다.
7. 종료 후 2.4초 안내, 이후 10초 결과 감상을 마치면 카메라를 끄고 로비로 돌아옵니다. **게임 그만하기 ×** 또는 다른 예제 탭으로 언제든 종료할 수 있습니다.

## 구성 및 불변 조건

- `src/main.ts`: 기존 해시 기반 예제 전환에 지연 로드 모듈을 추가합니다. 다른 탭으로 이동할 때 즉시 `dispose()`하고, 늦게 완료된 import는 현재 화면을 재확인합니다.
- `src/doodleface-game.ts`: 화면, 단일 카메라 수명, 단일 rAF, 순차 추론 스케줄러, 렌더링, 전환 레이어, 기존 PHOTO/VIDEO 캡처 제공자를 연결합니다.
- `src/doodleface-core.ts`: 좌표, 얼굴 부착점, Pinch, 획, 시간 상태를 DOM 없이 검증할 수 있습니다.
- `src/doodleface-vision.ts`: FaceLandmarker 1개(`numFaces:2`), HandLandmarker 1개(`numHands:2`)를 생성합니다. GPU 생성 실패 시 부분 생성된 객체를 닫고 CPU로 재시도합니다. 각 await 뒤 중단을 확인하며, 화면을 떠난 뒤 완성된 객체도 닫습니다.
- `src/doodleface.css`: DoodleFace 전용 스타일입니다. 기존 예제 스타일은 유지하고, 공통 탭만 항목이 늘어도 가로 스크롤로 읽을 수 있게 보완합니다.

원본 좌표 `x`를 `1-x`로 거울 변환한 중심이 `<0.5`이면 PLAYER 1, 아니면 PLAYER 2입니다. 각 점의 절반 로컬 좌표는 `xLocal = 2*(1-x)-playerIndex`, `yLocal=y`입니다. 결과 배열 순서와 handedness는 플레이어 번호를 결정하지 않습니다. 절반 경계를 넘어 움직이면 위치 기준 플레이어 배정도 바뀌므로 각자 자기 쪽에 머무릅니다.

카메라는 원본 오른쪽 절반을 PLAYER 1, 원본 왼쪽 절반을 PLAYER 2에 배정한 뒤 각각 cover·mirror 렌더링합니다. 얼굴이 없어도 매 렌더 프레임 카메라를 그리며 작은 반투명 WAITING 배지만 표시합니다. 두 패널의 cover 변환과 팔레트 위치는 프레임당 한 번 계산하고 모든 점에 재사용합니다.

각 낙서 점은 가장 가까운 대상 얼굴 랜드마크 번호와 얼굴 너비·회전 기준 오프셋을 저장합니다. 얼굴의 이동·크기·회전뿐 아니라 가까운 랜드마크의 표정 변화도 반영합니다. 추론 사이에는 직전 두 포즈로 최대 약 70ms 범위의 제한된 예측을 사용합니다. 새 점을 저장한 동일 프레임에서 렌더합니다.

Pinch 비율은 엄지·검지 거리 / 검지·소지 기저부 사이 손바닥 폭이며, 실제 영상 종횡비를 반영합니다. 시작 `<0.48`, 해제 `>0.67`로 히스테리시스를 적용하고 해제는 110ms 안정화 후 확정합니다. 220ms 이하 손 유실에는 마지막 펜과 획 상태를 유지합니다. 팔레트에서 시작한 Pinch와 얼굴 밖에서 시작한 Pinch는 얼굴 안으로 들어와도 새 획이 되지 않습니다.

프레임당 추론은 하나입니다. 준비·카운트다운·결과에서는 얼굴만 추론하고, 플레이 중에는 얼굴/손을 교대하며 Pinch 중에는 얼굴/손/손을 배정합니다. 4코어 이하 또는 4GB 이하 기기, 또는 느린 추론이 누적된 기기는 카메라 20fps, 추론 폭 480px, canvas DPR 1, 렌더 20fps로 낮춥니다. 기본은 카메라 30fps, 추론 폭 640px, DPR 최대 1.5, 렌더 30fps입니다.

## 로컬 모델

`public/mediapipe/`에 기존 `public/lemonade/`의 얼굴·손 모델을 복사했습니다. `wasm/`은 설치된 `@mediapipe/tasks-vision@1.0.1`의 WASM과 JS 로더를 복사하여 버전을 맞췄습니다. 기존 Lemonade 자산은 변경하지 않았습니다. 모델의 출처·해시는 `public/mediapipe/README.md`에 기록합니다. 패키지를 올릴 때는 WASM도 함께 갱신하고 실제 모델 브라우저 테스트를 다시 실행하세요.

## 검증

```sh
npm install
npm test
npm run build
npm run test:browser
```

Node 24 이상을 권장합니다(기존 테스트와 동일하게 TypeScript를 직접 읽습니다). 브라우저 테스트는 설치된 Google Chrome을 사용하며, 기존 개발 서버와 충돌하지 않도록 `127.0.0.1:5187`에 별도 Vite를 띄웁니다. 캡처·실패 추적은 `test-results/`에 저장합니다. 실제 사용자의 카메라나 영상은 테스트에 사용하지 않습니다.

단위 테스트: 좌우 배정, cover 역변환, 얼굴 부착점의 이동·확대·회전·표정 추적, 얼굴 내부 획 시작, Pinch 히스테리시스·유실, 안정 감지와 전체 시간 전이, 예측 제한.

브라우저 테스트: 실제 앱의 메뉴/해시, 도움말, 독립 팔레트, 모바일 배치, 가짜 카메라의 좌우 픽셀, 얼굴 미인식 시 영상 유지, 가로/세로 실제 Web Animations 전환, 교환 후 라벨과 영상, 획 표시, 프레임당 단일 추론, 종료 시점·자동 정리, 권한 거절·재시도, GPU 부분 실패·CPU 재시도, 모델 오류·늦은 생성 취소. 별도 테스트에서는 추론을 모킹하지 않고 실제 로컬 WASM과 두 모델을 생성·실행하고 외부 요청이 없는지 검사합니다.

물리 카메라 앞의 실제 두 사람에 대한 조명·가림·손 인식률은 자동 테스트로 보장하지 않습니다. 밝은 환경에서 카메라를 두 사람의 정면에 놓고, 각자 손 하나로 양쪽 팔레트·얼굴 경계·얼굴 회전·잠깐의 손 가림을 확인하는 실사용 점검이 필요합니다.

참고: [MediaPipe Web Hand Landmarker 공식 가이드](https://developers.google.cn/edge/mediapipe/solutions/vision/hand_landmarker/web_js). 동기식 VIDEO 추론 API와 옵션은 설치된 패키지의 `vision.d.ts`도 함께 확인했습니다.
